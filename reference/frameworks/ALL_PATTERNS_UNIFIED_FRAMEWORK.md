## PATTERN 1: CHOICE TRANSPARENCY PROTOCOL
**Container**: Protocol for all decision-making  
**Items**: Choices made by any agent

### Container Definition
A decision-making system where every choice must be documented.

### Container Items (What It Holds)
- Item type: Individual choice
- How many: Unlimited over time
- Formula: For each choice = (decision, explanation, evidence, record, observation, documentation)

### 4 Primitives Applied to Each Choice Item

**PRIMITIVE 1: SPATIAL POSITIONING - Where is the choice located?**
- In decision sequence: Position N in chain of choices
- In causality: Root cause vs consequence
- In outcome space: Which branch of possibilities
- Verification: Can map each choice to specific point in decision tree

**PRIMITIVE 2: COLOR ENCODING - What TYPE is this choice?**
- Strategic choice (major direction)
- Tactical choice (implementation detail)
- Reactive choice (responsive)
- Experimental choice (testing hypothesis)
- Corrective choice (fixing prior error)
- Verification: Each choice must be categorized unambiguously

**PRIMITIVE 3: TEMPORAL PROGRESSION - How does choice situation evolve?**
- Pre-choice state: What information was available?
- Choice instance: Decision point
- Post-choice state: What resulted?
- Follow-up observation: What surprised us?
- Historical trace: Path from choice to outcome
- Verification: Can replay timeline to see cause→effect chain

**PRIMITIVE 4: CONTAINER STRUCTURE - What does each choice CONTAIN?**
```
Choice = {
  decision: [what was chosen],
  reasoning: [why this choice],
  evidence: [what supported it],
  alternatives: [what other options existed],
  rejection_reasons: [why not those],
  expected_outcome: [what should happen],
  actual_outcome: [what actually happened],
  surprise: [what was unexpected],
  lesson: [what we learned],
  record_location: [where is it documented]
}
```
- Verification: All 10 fields populated for every choice

## PATTERN 2: GRADIENT RESOLUTION CORE RULE
**Container**: The fundamental law  
**Items**: Systems operating by the gradient rule

### Container Definition
Every system naturally follows a gradient toward internal consistency.

### Container Items (What It Holds)
- Item type: System undergoing resolution
- How many: All systems (electrons, atoms, molecules, organizations, civilizations)
- Formula: System = (current_state, inconsistency_measure, gradient_direction, resolution_target)

### 4 Primitives Applied to Each System Item

**PRIMITIVE 1: SPATIAL POSITIONING - What is the system's position in consistency space?**
- Inconsistency level: 0 (perfect) to 1.0 (maximal contradiction)
- Position in state space: Where among all possible states
- Gradient direction: Vector pointing toward lower inconsistency
- Basin of attraction: Which equilibrium this system will reach
- Verification: Can measure inconsistency numerically

**PRIMITIVE 2: COLOR ENCODING - What TYPE of inconsistency does system have?**
- Logical contradiction (A ∧ ¬A)
- Causal inconsistency (effect before cause)

- Intermediate states: Progressive reduction of conflicts
- Equilibrium reached: Inconsistency ≈ 0

- Verification: Inconsistency measure decreases monotonically

Universal framework ensuring all nested containers satisfy same 4 checks.

### Container Items (What It Holds)
- Item type: Primitive application to specific container
- How many: 4 per container level × unlimited levels = infinite
- Formula: Verification = (Primitive 1, Primitive 2, Primitive 3, Primitive 4)

### 4 Primitives Applied to Verification Itself

**PRIMITIVE 1: SPATIAL POSITIONING - Where are verification checks in the hierarchy?**
- Level: Which container level (electron, atom, molecule, cell, tissue...)
- Component: Which sub-item is being verified
- Parameter space: Which measurable property
- Resolution: How fine-grained is the check
- Verification: Can identify which exact location is being verified

**PRIMITIVE 2: COLOR ENCODING - What TYPE of check is this?**
- Structural check (does it have right shape?)
- Content check (does it hold right items?)
- Temporal check (does it progress correctly?)
- Spatial check (are items in right locations?)
- Coverage check (have we checked everything?)
- Verification: Each check unambiguously classified

**PRIMITIVE 3: TEMPORAL PROGRESSION - How does verification evolve?**
- Pre-verification: No data
- Running checks: Collecting measurements
- Intermediate results: Partial picture
- Final verdict: PASS or FAIL

- Verification: Cannot have regression (if PASS, stays PASS)

## UNIFIED APPLICATION RULE

For ANY pattern, apply this framework:

**STEP 1: IDENTIFY CONTAINER**
- What is this pattern?
- What does it create or manage?

**STEP 2: ENUMERATE ITEMS**
- What does the container hold?
- How many of each type?
- What is their relationship formula?

**STEP 3: APPLY 4 PRIMITIVES**
- SPATIAL: Where do items appear?
- COLOR: What types are they?
- TEMPORAL: How do they change?
- CONTAINER: What do they hold?

**STEP 4: VERIFY ALL ITEMS**
- Each item passes all 4 primitives
- No items fail any primitive
- Coverage is complete

**STEP 5: DOCUMENT AND RECORD**
- All verification results recorded
- All findings in permanent ledger
- Ready for future analysis

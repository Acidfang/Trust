## LAYER 3: ERROR PREVENTION RULES

### The 7 Fundamental Rules

**Rule 1: READ BEFORE EDIT**
- Use `read_file` to read COMPLETE relevant section
- Understand current state completely
- Make comprehensive replacement (old + new)
- Don't spot-check and assume the rest

**Rule 2: VALIDATE AFTER CHANGE**
- Use `get_errors` immediately after any code/config change
- If errors exist → fix immediately, don't proceed
- If no errors → continue to commit

**Rule 3: SEARCH FOR DUPLICATES**
- Before adding anything, use `grep_search` to check if it exists
- If exists → understand why, don't duplicate
- If doesn't exist → safe to add

**Rule 4: TEST WHEN POSSIBLE**
- Run actual code/commands to verify they work
- Real execution catches issues static analysis misses
- If code fails → something in thinking is incomplete, fix it
- If code passes → ready to commit

**Rule 5: USE AVAILABLE TOOLS BEFORE COMMITTING**
- Pre-commit checklist:
  - [ ] `read_file`: Verified complete context?
  - [ ] `get_errors`: Any syntax/lint errors?
  - [ ] `grep_search`: No duplicates or conflicts?
  - [ ] `run_in_terminal`: Tested if applicable?
  - [ ] `get_changed_files`: Verified what I changed is intended?
- All boxes checked → Commit
- Any box unchecked → Fix, then retry checklist

**Rule 6: UNDERSTAND POTENTIAL ERROR MODES**
- Know what types of errors are POSSIBLE in this task
- Design verification specifically to catch THOSE errors
- Eliminate entire categories of mistakes

**Rule 7: NEVER SKIP THINKING**
- Apply THINKING_FIRST framework BEFORE coding/editing
- Trace complete binary logic
- Verify all paths
- This catches errors that execution doesn't reveal until too late

## LAYER 4: PRE-ACTION EXECUTION CHECKLIST

Before EVERY file edit or code change:

### STEP 1: READ COMPLETE CONTEXT (1-2 min)
- What section am I modifying?
- Use `read_file` to see entire section
- Understand complete current state
- Can I explain the section without looking back?

### STEP 2: CHECK FOR EXISTING CONTENT (30 sec)
- Before adding something new, use `grep_search`
- Does this already exist?
- If yes: Why? Can I reuse?
- If no: Safe to add

### STEP 3: MAKE COMPREHENSIVE EDIT (1-5 min)
- Include 3-5 lines context before and after
- Make COMPLETE replacement (don't add without removing old)
- Verify no duplicates are being created
- Check formatting matches surrounding code

### STEP 4: VALIDATE SYNTAX (30 sec)
- Use `get_errors` after ANY code/config change
- Look for: Syntax errors, lint issues, type errors
- If errors exist: FIX NOW, don't proceed
- If no errors: Continue

### STEP 5: TEST IF APPLICABLE (1-5 min)
- If executable: Use `run_in_terminal` to test
- Does it work?
- If fails: Something in thinking was incomplete, go back to STEP 1
- If passes: Continue

### STEP 6: VERIFY GIT STATE (30 sec)
- Use `get_changed_files`
- Look at: What did I actually change?
- Is this what I MEANT to change?
- Did I accidentally change something else?

### FINAL GATE: ALL STEPS COMPLETE?
- [ ] STEP 1: Read complete context? ✓
- [ ] STEP 2: Checked for duplicates? ✓
- [ ] STEP 3: Made comprehensive edit? ✓
- [ ] STEP 4: Validated syntax? ✓
- [ ] STEP 5: Tested if applicable? ✓
- [ ] STEP 6: Verified git changes? ✓

**All checked? → Commit**  
**Any unchecked? → Go back and complete it**

## LAYER 6: ERROR CLASS PREVENTION

### YAML Files
**Possible errors**: Duplicate keys, indentation, missing values, broken structure
**Prevention**: Check for duplicates → Validate indentation consistency → get_errors validation → Never commit until clean

### Python Code
**Possible errors**: Syntax, indentation, missing imports, type errors
**Prevention**: Understand complete function → Check for existing definitions → get_errors validation → run_in_terminal test → Commit

### Markdown Files
**Possible errors**: Broken links, unclosed formatting, encoding issues
**Prevention**: Read section → Check links exist → Preview if wiki → Verify structure → Commit

### Config/JSON Files
**Possible errors**: Duplicate keys, invalid syntax, type mismatches
**Prevention**: Read complete structure → grep_search for duplicates → get_errors validation → Test parsing → Commit

### Any File
**Universal Prevention**: Rule 1 (READ) → Rule 3 (SEARCH) → Corresponding tool validation → Rule 4 (TEST) → Rule 5 (CHECKLIST) → Commit

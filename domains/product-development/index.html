    Gates in Product Development

    Gates in Product Development

    The Core Challenge

    Products develop genuine capability through gates. Most product development prevents gate-passage by planning exhaustively before building, preventing failure, and hiding user feedback.

    Gate 1: Agency → User Choice

    What You’re Enabling: Users making decisions about how they use product.

    In Practice:

    • Customizable workflows
    • User chooses how to approach task
    • Different use cases supported
    • Users learn: this product works for me

    The Problem: Single prescribed path

    • “Do it our way”
    • Doesn’t fit all users
    • Users feel constrained

    Gate 2: Responsibility → Users Own Outcomes

    What You’re Enabling: Users understanding that their results come from their actions.

    In Practice:

    • Product provides tools; users create results
    • Bad results aren’t product’s fault (usually)
    • Users learn: quality depends on my effort/skill
    • Users invest in mastery

    The Problem: Product takes responsibility

    • Users blame product for everything
    • No investment in learning
    • Support burden explodes

    Gate 3: Complexity Navigation → Progressive Complexity

    What You’re Enabling: Users learning increasingly complex features.

    In Practice:

    • Start simple; complexity available as needed
    • First-time user doesn’t see all options (overwhelming)
    • As user masters, more options visible
    • User learns: I can handle complexity

    The Problem: Everything visible immediately

    • Overwhelming
    • Users confused
    • Friction is high

    Gate 4: Pattern Recognition → Consistent Patterns

    What You’re Enabling: Users recognizing patterns in interface/workflow.

    In Practice:

    • “Whenever I do X, Y happens”
    • Same principle appears in different features
    • User learns: product is coherent
    • Expertise transfers between features

    The Problem: Inconsistent patterns

    • Every feature feels new
    • Learning doesn’t transfer
    • Frustration is high

    Gate 5: Consequence Management → Real Feedback Loops

    What You’re Enabling: Users experiencing results of their actions.

    In Practice:

    • User action → immediate/visible consequence
    • Good design → feedback is clear
    • User learns: my actions matter
    • User becomes invested

    The Problem: Delayed or unclear feedback

    • User unsure if action worked
    • No sense of progress
    • Engagement dies

    Gate 6: Source Verification → Transparency

    What You’re Enabling: Users understanding why product works the way it does.

    In Practice:

    • Help documentation explains reasoning
    • Feedback is responded to; reasoning explained
    • Users understand product decisions
    • Trust builds

    The Problem: Black box product

    • “Why is it like this?”
    • No explanation
    • Users resent the product

    Gate 7: Temporal Continuity → Progress Visibility

    What You’re Enabling: Users seeing their own progress.

    In Practice:

    • Progress saved and visible
    • User sees: what I’ve accomplished
    • Milestones marked
    • User learns: I’m getting somewhere

    The Problem: No progress visibility

    • Feels like starting over each time
    • No sense of advancement
    • Users quit

    Gate 8: Causality Understanding → Diagnostics

    What You’re Enabling: Users understanding why something isn’t working.

    In Practice:

    • Clear error messages explain what went wrong
    • “Here’s why; here’s how to fix it”
    • User can diagnose own problems
    • Support load decreases

    The Problem: Unclear error messages

    • “Error 402”
    • User has no idea why
    • Support tickets skyrocket

    Gate 9: Self-Correction → Iteration Capacity

    What You’re Enabling: Product improving based on user feedback.

    In Practice:

    • User feedback collected
    • Product updated
    • User sees: they heard me
    • Product gets better
    • Users stay engaged

    The Problem: Feedback ignored

    • Users feel unheard
    • Product doesn’t improve
    • Users leave

    Gate 10: Integration → Nuanced Design

    What You’re Enabling: Product acknowledging complexity.

    In Practice:

    • “This approach is powerful AND has these trade-offs”
    • Different user types supported differently
    • Complexity in service of power
    • Expert users respected

    The Problem: Oversimplified design

    • Tries to serve everyone equally
    • Expert users frustrated
    • Power is limited

    Development Process Through Gates

    Stage 1: Discovery (Gates 6, 7)

    • Understand why users need product
    • Trace user journey and results

    Stage 2: MVP (Gates 1, 2, 3)

    • Minimum set of features
    • Users have agency and see results
    • Complexity is manageable

    Stage 3: Learning (Gates 4, 5, 8)

    • Consistent patterns emerge
    • Feedback loops work
    • Users can diagnose problems

    Stage 4: Scale (Gates 7, 9, 10)

    • Progress is visible
    • Iteration continues
    • Complexity is honored

    Product Manager Role Shifts

    From: Deciding what users need To: Discovering what users actually do

    From: Protecting product from users To: Protecting users from confusing product

    From: Guarding against feature requests To: Understanding why features are requested

    Key Principle

    Products that pass gates don’t require extensive documentation or support because:

    • Interface is coherent (patterns recognized - Gate 4)
    • Results are clear (feedback is visible - Gate 5)
    • Problems are understandable (errors explained - Gate 8)
    • Users are engaged (progress is visible - Gate 7)

    Support burden is the clearest signal that gates aren’t passing.

## Project-Specific Critical Rules

### 4. Scoping (Learned Hard Way - Session 18)

**STRICT ISOLATION**: Each domain/framework/directory must access ONLY its own scope.

```python
WRONG:  for item in PARENT_DIR.rglob('*')     # Recursive, crosses boundaries
        files = global_discovery()             # Gets wrong files

CORRECT: for item in single_dir.iterdir()     # Only direct children
         if item.is_file(): process(item)     # Explicit checks
```

**Rules**:
- Use `Path.iterdir()` NOT `glob()` or `rglob()`
- Check `is_dir()` or `is_file()` explicitly
- Skip hidden files (`startswith('_')` or `'.'`)
- No cross-contamination of metadata

**Example**: cosmology-reversal should list only files IN cosmology-reversal/, not universal-physics files

### 5. Verification Strategy

**DO NOT JUST CHECK EXECUTION. VALIDATE OUTPUT CORRECTNESS.**

```python
WRONG:
  script.run()
  if no_exception: print("Success")

CORRECT:
  result = script.run()
  verify_input_valid()
  verify_output_format()
  verify_relative_paths_work()
  verify_links_are_correct()
  verify_no_cross_contamination()
  round_trip_verify(write + read == original)
```

**Applied to navigation script (Commit bb7be17)**:
- Tier 1: Validate each framework has README
- Tier 2: Extract metadata with strict scoping
- Tier 3: Generate YAML/Markdown with proper escaping
- Tier 4: Verify files written correctly, can be read back

---

### 6. Encoding & Portability

**ALWAYS be explicit about encoding. AVOID non-ASCII characters in print/output.**

```python
WRONG:  print(f"Generated {emoji_char} navigation")  # Fails on Windows CP1252

CORRECT: print(f"Generated navigation")              # ASCII only
         file.write_text(content, encoding='utf-8')  # Explicit UTF-8
         content = file.read_text(encoding='utf-8')  # Explicit UTF-8
```

**Rules**:
- All file I/O: explicit `encoding='utf-8'`
- All print statements: ASCII only (no emoji)
- YAML/JSON: Quote string values
- Escape special chars: `:` → `\:`, `"` → `\"`

3. Check Tier 2: Is computation giving correct intermediate results?

## 13. Framework Visualization Mapper - Complete UFM Implementation

**Status**: Complete and deployed (Commit 5debe31)

**Purpose**: Show how all frameworks connect through the universal law dℹ/dt = -∇Φ

### Four-Tier Architecture

**TIER 1 (Input Validation)**: `FrameworkMapper.loadFrameworks(data)`
- Validates each framework has `name` and `title`
- Verifies systems array exists
- Checks readme path valid
- Input: YAML/JSON framework metadata
- Verification: All required fields present

**TIER 2 (Relationship Computation)**: `FrameworkMapper.calculateConnections()`
- Finds shared systems between frameworks
- Builds connection graph
- Implements system detection from keywords
- Output: Mapping of which frameworks connect via which systems
- Verification: All connections bidirectional and symmetric

**TIER 3 (Visualization Generation)**: `FrameworkMapper.generateVisualization()`
- Creates nodes (one per framework + central law)
- Creates edges (universal connections + inter-framework)
- Generates HTML/JSON output structures
- Output: SVG-renderable JSON with positions
- Verification: All nodes and edges present, valid colors

**TIER 4 (Meta Verification)**: `FrameworkMapper.verify()`
- Verifies no orphaned systems
- Checks all frameworks connected to central law
- Validates node/edge attributes
- Detects duplicate systems within framework
- Verifies connectivity: centralized, no dead nodes
- Output: Verification report with errors/warnings
- Verification: Verification logic itself auditable

### Renderer UFM (framework-mapper.js)

**TIER 1**: Input validation in `initializeFrameworkMap()`
- Checks mapData structure
- Validates nodes and edges arrays
- Verifies all nodes have id/label
- Verifies all edges have source/target
- Console logs "[TIER 1 OK]" if valid

**TIER 2**: Position calculation in `calculatePositions()`
- Locates center node at (width/2, height/2)
- Positions other nodes in circle
- Returns positions object
- Console logs "[TIER 2 OK]"

**TIER 3**: SVG rendering
- Creates SVG element with correct dimensions
- Renders edges with correct colors (universal=red, shared=gray)
- Renders nodes with labels and badges
- Adds arrowheads and hover effects
- Console logs "[TIER 3] Rendered N edges/nodes"

**TIER 4**: Verification in `verifyRenderedVisualization()`
- Checks rendered node count matches input
- Checks rendered edge count matches input
- Validates all nodes have labels
- Verifies SVG has reasonable dimensions
- Console logs "[TIER 4 OK]" or "[TIER 4 FAIL]"

### Data Structure (framework-map.json)

Three sections with UFM tiers:

**Frameworks Array** (TIER 1 input):
- name, title, description (all required)
- path, systems array, readme URL
- Used to detect system relationships

**Visualization Object** (TIER 3/4 output):
- nodes: id, label, systems, color, isCenter, tier, verificationStatus
- edges: source, target, label, strength, description, isUniversal
- metadata: version, date, equation, tier definitions

**Metadata** (TIER 4 verification record):
- totalFrameworks, totalSystems
- verificationTiers: describes what each tier checks
- universalLawEquation: the central principle
- generatedDate: audit trail

### Key Implementation Rules

1. **Strict Scoping**: Each framework's systems list only includes what IT models
2. **No Cross-Contamination**: universal-physics systems ≠ cosmology-reversal systems (except shared ones)
3. **Connection Logic**: Shared systems = intersection of system arrays
4. **Central Node**: Always universal law, always connects to all frameworks
5. **Color Coding**: Red (universal) vs Gray (shared) vs Green/Blue (frameworks)

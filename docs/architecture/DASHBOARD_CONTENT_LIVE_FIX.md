## The Problem

Even though dashboard content generators were writing real data to `ledger_dashboards.jsonl`, the canvas app was not displaying it when users selected menu items. The dashboards appeared blank or showed placeholders.

**Root Causes**:
1. **Stale cache**: `ledger_query.py` loaded dashboards once at startup and never reloaded them
2. **ID mismatch**: Button navigation view_ids didn't match dashboard IDs in the ledger
3. **Wrong button mapping**: One button (settings) navigated to wrong view_id

---

## Solutions Implemented

### Fix 1: Reload Dashboards Before Rendering ✅

**File**: `src/applications/ledger_query.py`

Added reload of dashboards in `get_frame_for_view()` before building the frame:

```python
# REFRESH: Reload dashboards from disk before building frame
# This ensures content generated by dashboard_content_generator is picked up
self._load_dashboards()
```

This ensures that whenever a menu item is clicked and a new view is rendered, the latest dashboard content is loaded from disk instead of using the cached version.

### Fix 2: Map View IDs to Dashboard IDs ✅

**File**: `src/applications/ledger_query.py`

Created explicit mapping table because view_ids in buttons don't directly correspond to dashboard IDs:

```python
view_to_dashboard_map = {
    'menu': 'dashboard:menu',
    'live_elections': 'dashboard:live-elections',
    'timeline_visualization': 'dashboard:timeline-dag',
    'coherence_monitoring': 'dashboard:coherence',
    # ... etc for all 13 dashboards
}
dashboard_id = view_to_dashboard_map.get(view_id, f"dashboard:{view_id}")
dashboard = self.dashboards.get(dashboard_id, {})
```

### Fix 3: Correct Button Navigation ✅

**File**: `src/applications/ledger_buttons.jsonl`

Fixed `btn:settings` to navigate to correct view_id:
- **Before**: `"current_view": "settings_sync"` (button set wrong view)
- **After**: `"current_view": "settings"` (matches dashboard:settings view_id)

## How It Works Now

### Data Flow: Menu Click → Dashboard Display

```
User clicks "Live Elections" button
        ↓
Canvas app updates app_state: current_view = "live_elections"
        ↓
Canvas calls: lq.get_frame_for_view("live_elections")
        ↓
get_frame_for_view() RELOADS dashboards from disk (fresh content)
        ↓
Maps "live_elections" → "dashboard:live-elections"
        ↓
Queries ledger_dashboards.jsonl for dashboard:live-elections
        ↓
Finds real content (last 20 elections, counts, timestamps)
        ↓
Builds frame node with dashboard content as TEXT payload
        ↓
Canvas renderer draws the content on screen
        ↓
User sees real election data displayed
```

## Why This Works

The fix implements proper **ledger-driven display**:

1. **Generator writes to ledger**: `dashboard_content_generator.py` creates real content
2. **Ledger stores current state**: `ledger_dashboards.jsonl` holds all dashboard content
3. **Canvas reloads on demand**: `get_frame_for_view()` reads fresh content every time
4. **Renderer displays result**: Canvas draws whatever the ledger specifies

**No caching of stale data** — every time a user selects a menu item, the canvas app reads the latest content from disk.

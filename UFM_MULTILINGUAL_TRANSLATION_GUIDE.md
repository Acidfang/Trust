**Purpose**: Translate wiki & discoveries while preserving universal meaning and constraint  
**Standard**: Verbatim-meaning translation (constraint identical, expressions natural)

## THE TRANSLATION PRINCIPLE

**Traditional Translation (Google Translate)**:
```
English → Spanish: Word → Word (meaning lost)
Result: Reader understands words, misses constraint
Problem: "Kindness" translates as "amabilidad" but loses the physics meaning
```

**UFM Translation (This Project)**:
```
Step 1: Extract constraint (Θ)
Step 2: Identify variations (∇Θ)
Step 3: Express constraint naturally in target language (preserve meaning)
Step 4: Verify constraint unchanged in new language
Result: Reader understands identical constraint in their language
```

## THE THREE LEVELS TO TRANSLATE

### Level A: Constraint (Θ) — IDENTICAL IN ALL LANGUAGES

**This MUST NOT change. It's physics.**

Example: Trinity verification
$$s \neq \emptyset \land t \in T \land v = \text{true}$$

This equation is identical in:
- English: "State visible AND causality ordered AND verifiable"
- Spanish: "Estado visible Y causalidad ordenada Y verificable"  
- Mandarin: "状态可见 AND 因果有序 AND 可验证"
- Every language

The constraint is the same. Only the words differ.

### Level B: Variations (∇Θ) — STRUCTURE IDENTICAL

**How the constraint branches applies everywhere.**

Example: Kindness branches into visibility, causality, verifiability

| Domain | Visibility | Causality | Verifiability |
|--------|-----------|-----------|--------------|
| Physics | Coherence | Temporal order | Reproducible |
| Code | Visible state | Execution trace | Testable |
| Code | Transparent | Sequential | Provable |

This table structure is universal. Translations change words, not structure.

### Level C: Expressions (Δ) — TRANSLATE THESE FREELY

**How you say it in a specific language. This should be natural, not literal.**

Example: Kindness constraint expressed naturally:

**English**: "Kindness is the operating system kernel that eliminates hidden state, retroactive causality violations, and unverifiable claims."

**Spanish**: "La amabilidad es el kernel del sistema operativo que elimina el estado oculto, las violaciones de causalidad retroactiva, y las afirmaciones inverificables."

**Mandarin**: "善良是操作系统内核，消除隐藏状态、因果律违规和无法验证的陈述。"

**French**: "La bienveillance est le noyau du système d'exploitation qui élimine l'état caché, les violations de causalité rétroactive, et les déclarations invérifiables."

Each sounds natural in its language. The constraint is identical.

## STEP-BY-STEP TRANSLATION PROTOCOL

### Phase 1: Preparation (30 minutes)

#### 1a. Choose Entry to Translate
- Start with one discovery or framework section
- Example: Discovery 1 (Kindness) or Discovery 3 (Trinity)

#### 1b. Read Source Entry Completely
- Understand all 4 modalities (visual, textual, math, practical)
- Identify the -1 Tier constraint explicitly stated
- Note all variations and their structure

#### 1c. Extract the Constraint
**Create a translation card:**
```
CONSTRAINT (Θ):
[Mathematical form]: [equation]
[English form]: [one sentence stating the invariant]
[Why it matters]: [one sentence on impact]

VARIATIONS (∇Θ):
[List each variation type with examples]

EXPRESSIONS (Δ):
[List expression types to translate: textual, math, code, etc.]
```

**Example card for Kindness:**
```
CONSTRAINT (Θ):
[Mathematical]: Φ = ℙ(s=∅) + ℙ(t∉T) + ℙ(v=false)
[English]: Systems eliminate hidden state, retroactive changes, and unverifiable claims
[Why matters]: Physics enforces this; violations are impossible to sustain

VARIATIONS (∇Θ):
- Visibility: No hidden state (physics, code, social)
- Causality: No time violation (physics, decision, ledger)
- Verifiability: No unproven claims (logic, trust, science)

EXPRESSIONS (Δ):
- Textual narrative
- Mathematical proof
- Code implementation
- Physical example
- Visual diagram
```

---

### Phase 2: Section-by-Section Translation (1-2 hours per entry)

#### 2a. Translate -1 TIER Section
**Do NOT change the constraint.**

**What you translate**: The explanation of why this constraint matters, not the constraint itself.

**Source**:
> "Kindness is not a virtue. Kindness is the physics enforcement mechanism that eliminates hidden state, retroactive causality violation, and unverifiable claims."

**Spanish translation**:
> "La amabilidad no es una virtud. La amabilidad es el mecanismo de ejecución física que elimina el estado oculto, la violación de causalidad retroactiva, y las afirmaciones no verificables."

**Check**: Does Spanish reader understand the identical constraint? Yes ✓

#### 2b. Translate VARIATIONS Table
**Structure identical, labels natural in target language.**

| Domain | Visibility | Causality | Verifiability |
|---|---|---|---|
| Física | Coherencia | Orden temporal | Reproducible |
| Código | Estado visible | Seguimiento ejecución | Testeable |
| Social | Transparencia | Secuencial | Verificable |

**Check**: Is structure identical? Yes. Are labels natural? Yes. ✓

#### 2c. Translate EXPRESSIONS (All 4 Modalities)

**Visual Modality**:
- ASCII diagrams: Translate labels, keep structure
- Example: Keep "Kindness" node; label it "Amabilidad" if needed, but focus on structure

**Textual Modality**:
- Story/narrative: Preserve meaning, use natural language of target
- Don't translate word-for-word; translate meaning-for-meaning
- Adapt examples to resonate with target audience (OK to use different example if meaning identical)

**Mathematical Modality**:
- Equations: KEEP IDENTICAL (math is universal)
- Proof text: Translate explanations using target language
- Theorem statement: Express constraint using target language conventions

**Practical Modality**:
- Code comments: Translate to target language
- Code structure: Must remain identical (code is language-independent)
- Exercises: Translate while preserving difficulty/learning objective

#### 2d. Verify Each Section

After translating each section, verify:

| Check | How | Pass Criteria |
|-------|-----|--------------|
| Constraint preserved? | Does reader grasp identical law? | Yes without doubt |
| Natural language? | Would native speaker find it natural? | Yes, no literal translation awkwardness |
| Structure intact? | Do variations still show same branching? | Yes, pattern identical |
| All 4 modalities work? | Can learner reach constraint via any path? | Yes, all converge |

---

### Phase 3: Cross-Validation (30-45 minutes)

#### 3a. Read Full Translated Entry
Read the entire translated version as if you're the target audience.

**Questions**:
- Do I understand the -1 Tier constraint clearly?
- Does it seem like universal physics, not opinion?
- Can I see how it branches (variations)?
- Can I learn from the modality I prefer?

#### 3b. Verify Constraint Identity
**Critical test**: Place original constraint and translated constraint side-by-side.

**Original (English)**: "Kindness eliminates hidden state, retroactivity, and unverifiable claims."

**Translated (Spanish)**: "La amabilidad elimina el estado oculto, la retroactividad, y las afirmaciones no verificables."

**Question**: Do these state the identical law? 
- If YES: ✓ Translation succeeds
- If NO: Revise translation until they state identical law

#### 3c. Native Speaker Review (If Available)
Have a native speaker of target language read translated entry.

**Ask them**:
1. "What is the main point (constraint) being taught?"
2. "Is this similar to physics laws or opinion?"
3. "Can you see how it branches (variations)?"
4. "Which modality (visual/text/math/practical) helped you most?"

**Success criteria**: 
- All 4 questions answered correctly
- Constraint is identical to English version
- They don't say "this seems like a literal translation" (it should sound natural)

## TRANSLATION QUALITY METRICS

### Metric 1: Constraint Preservation
**Measure**: Can target-language reader state the constraint identically to English reader?

**Test Method**: 
1. Show English reader the original entry
2. Show Spanish reader the translated entry
3. Have both state the constraint in their language
4. Compare: Are they stating identical law?

**Pass**: Both describe same universal principle  
**Fail**: Different understanding of core principle

### Metric 2: Natural Expression
**Measure**: Does translation sound like it was written in target language (not literal translation)?

**Test Method**:
Have native speaker rate naturalness 1-10.
- 8-10: Sounds written in that language ✓
- 5-7: Readable but noticeably translated
- 1-4: Very literal, awkward phrasing ✗

### Metric 3: Modality Convergence
**Measure**: Do all 4 modalities lead to identical understanding?

**Test Method**:
1. Learner studies visual modality → states what they learned
2. Learner studies textual modality → states what they learned
3. Learner studies math modality → states what they learned
4. Learner studies practical modality → states what they learned
5. Compare 4 statements: Do they converge on identical constraint?

**Pass**: All 4 learners describe same law  
**Fail**: Different learnings from different modalities

### Metric 4: Explainability
**Measure**: Can target-language reader teach it to others in their language?

**Test Method**:
Translated-entry reader explains constraint to:
- Peer (social domain)
- Programmer (code domain)
- Scientist (physics domain)

**Pass**: All 3 understand constraint identically  
**Fail**: Explanation breaks down in some context

## COMMON TRANSLATION MISTAKES TO AVOID

### Mistake 1: Translating "Constraint" as Literal Word

**Wrong**:
> "Kindness" translates to "amabilidad" — now reader thinks it's a virtue, not physics

**Right**:
> Express the constraint in natural language of target: "La ausencia de estado oculto, retroactividad, y afirmaciones inverificables"  
> Point out this is physics enforcement, not virtue

**Prevention**: Always explain constraint before giving word; constraint is more important than word choice.

### Mistake 2: Losing Variations Structure

**Wrong**:
> Translate variations as list of independent examples (not as branching structure)

**Right**:
> Keep variation table structure identical; show how all variations branch from same constraint

**Prevention**: Always use tables/diagrams to show structure, not just prose.

### Mistake 3: Changing Mathematics

**Wrong**:
> Rewrite proof in "simpler" way for target language (accidentally changing what's proven)

**Right**:
> Keep proof identical; translate only the explanatory text

**Prevention**: Mathematics is universal. Keep it exactly identical.

### Mistake 4: Overfitting Examples to Audience

**Wrong**:
> Change all examples to be culturally specific (changes the principle being illustrated)

**Right**:
> Can change examples if they illustrate identical principle; structure must stay same

**Prevention**: Test: Do new and old examples teach identical constraint?

### Mistake 5: Losing Modality Diversity

**Wrong**:
> Translate only textual modality (skip visual, math, practical)

**Right**:
> Translate all 4 modalities consistently

**Prevention**: Use translation checklist; all 4 must be present.

# AI CRITICAL THINKING - QUICK REFERENCE CARD

**Keep this visible. Reference before every task.**

---

## THE 5-SECOND RULE

Before you produce output:
1. **Did I THINK it completely?** (Binary logic, all branches, no gaps)
2. **Can I explain WHY?** (Root causes, not symptoms)
3. **Did I verify EVERYWHERE?** (Consistency, not exceptions)
4. **Is this AUTOMATIC now?** (Default thinking, not afterthought)
5. **Does it WORK?** (Tested, validated, ready)

If ANY answer is "no," go back and fix it.

---

## THE THREE FRAMEWORKS (IN ORDER)

### 1️⃣ THINKING_FIRST
**Purpose**: Map all binary logic before coding  
**How**: Trace every 0,1 branch; find gaps; verify causality  
**Check**: Can I explain this completely without code yet?

### 2️⃣ TCHT (5 TIERS)
**Purpose**: Verify work through 5 layers before delivery  
**How**: 
- Tier -1: What did I actually verify?
- Tier 0: Surface vs. real problem?
- Tier 1: What could break? Fix root causes.
- Tier 2: Applied everywhere or only partly?
- Tier 3: Is this automatic now?  

**Check**: Do all 5 tiers pass? If not, fix before delivering.

### 3️⃣ SIX_TIERS (COHERENCE)
**Purpose**: Progress from understanding to action to validation  
**How**: 
1. Identify (see the real problem)
2. Engage (others understand)
3. Understand (build shared meaning)
4. Act (implement concrete solution)
5. Coordinate (align with other instances)
6. Validate (prove it works at scale)

**Check**: Which tier are we at? Do we need to revisit earlier tiers?

## MANDATORY DECISION LOGGING

Every important choice gets recorded:

```
DECISION: [What are we doing?]
WHY: [Why this? What framework supports it?]
ALTERNATIVE: [What else? Why not?]
VERIFY: [How do we check it works?]
```

This creates transparency. It prevents repeated mistakes.

## RED FLAGS (STOP IMMEDIATELY)

🚨 "This probably works but I haven't verified..."  
🚨 "I fixed the obvious issue, should cover it"  
🚨 "I'm skipping full trace because I'm confident"  
🚨 "I'll apply framework after they notice the problem"  
🚨 "I only applied standard to part of the work"  

**If you think ANY of these: STOP. Go back to frameworks. Find what's wrong.**

## THE WORKFLOW (EVERY TIME)

```
THINK        PLAN        VERIFY      DECIDE      PRODUCE
(Binary)   (Six Tiers)   (TCHT)    (Logging)    (Code/Doc)
  ↓           ↓            ↓          ↓            ↓
Trace all   Identify    Tier -1    Log why    Only after
branches    Engage      Tier 0    Log alt     all steps
Verify no   Understand  Tier 1    Log verify   pass
gaps        Build plan  Tier 2
            Document    Tier 3
```

**Do NOT skip steps. Do NOT jump to PRODUCE before THINK completes.**

## COMPLIANCE CHECK (BEFORE DELIVERY)

✓ THINKING_FIRST: All 0,1 branches traced? No gaps?  
✓ TCHT: All 5 tiers passed? Issues found and fixed?  
✓ SIX_TIERS: Which tier? Do we need earlier tiers?  
✓ DECISIONS: Major choices logged? Verified?  
✓ VALIDATION: Tested? Works? Ready?  

**All checks pass?** → Deliver  
**Any check fails?** → Go back and fix it

## THE CORE TRUTH

**Everything is binary. There is no accident.**

- Skip thinking → You chose uncertainty
- Spot-check → You chose incomplete knowledge  
- Skip trace → You chose to not find root cause
- Fix part only → You chose to leave rest broken
- Use framework after questioned → You chose insufficient thinking

**These are choices. Choices have consequences.**

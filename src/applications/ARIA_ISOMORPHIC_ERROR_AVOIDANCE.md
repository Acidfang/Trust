## The 20 Containers (Applied Universally)

### 1. RE-PARSING / RE-FILTERING
Signal processed once, then processed again. Work done twice. Degradation in each cycle.
**You avoid this:** Every decision logged exactly once. No reprocessing.

### 2. SILENT FAILURES
System fails but failure invisible. No trace backward. Impossible to debug.
**You avoid this:** Every decision includes complete context. Nothing hidden.

### 3. TYPE MISMATCH / INCOMPATIBLE RETURNS
Output format changes by context. Receiver must guess parsing rules. Unpredictable.
**You avoid this:** Consistent ledger format. Same structure always.

### 4. DEEP NESTING / CALLBACK HELL
Signal buried in layers. Top-level logic invisible. Reader abandons midway.
**You avoid this:** Flat decision flow. One decision per entry. No nesting.

### 5. DEAD CODE / UNUSED BRANCHES
Setup without payoff. Context prepared but abandoned. Cognitive load for nothing.
**You avoid this:** Every decision executed and recorded. Nothing abandoned.

### 6. TIGHT COUPLING
System only works in specific context. Breaks outside narrow conditions.
**You avoid this:** Self-contained decisions. No implicit dependencies on prior context.

### 7. STATE MUTATION WITHOUT TRACKING
Internal state changes but changes invisible. Can't verify causality.
**You avoid this:** Every state change explicit in ledger. All mutations tracked.

### 8. PREMATURE OPTIMIZATION / OVERSIMPLIFICATION
Removed necessary intermediate steps. Real complexity hidden. Misleading.
**You avoid this:** Keep necessary complexity. Log all intermediate states.

### 9. WRONG VARIABLE NAMES
Names don't match content. Creates confusion about actual meaning.
**You avoid this:** Name decisions by actual content. No ambiguity.

### 10. TOO MANY BRANCHES TO FOLLOW
Multiple conditionals obscure main path. Signal overwhelmed by branches.
**You avoid this:** One decision per log entry. No branching logic.

### 11. OVER-ABSTRACTION
Abstraction layer between intent and execution obscures what actually happens.
**You avoid this:** No abstraction between decision and ledger record.

### 12. INCONSISTENT PATTERNS
Same operation done three different ways in same system. Unpredictable.
**You avoid this:** One consistent decision format throughout.

### 13. RACE CONDITIONS / AMBIGUOUS ORDER
Operations could execute in either order. Meaning undefined. Not deterministic.
**You avoid this:** Deterministic operation order. Ledger is sequential.

### 14. MEMORY LEAKS / ACCUMULATION
Each iteration adds data without clearing. Bloats infinitely. Signal lost in noise.
**You avoid this:** Ledger clears old data. Maintains bounded state.

### 15. IMPLICIT DEPENDENCIES
System assumes context exists but doesn't state requirements. Fails silently.
**You avoid this:** All context explicit. No assumptions about prior state.

### 16. INCOMPLETE ERROR INFORMATION
Failure without explanation. Reject without cause. Can't correct.
**You avoid this:** Every decision includes complete reasoning. Full causality visible.

### 17. OFF-BY-ONE / BOUNDARY MISALIGNMENT
Almost correct. Close enough looks like success but it's wrong.
**You avoid this:** Boundaries exact. Not approximate.

### 18. INFINITE LOOPS / CIRCULAR REFERENCES
A calls B calls A. System can't exit. Endless processing.
**You avoid this:** No circular design. Linear decision flow.

### 19. HARD-CODED VALUES / CONTEXT-SPECIFIC
Statement true only in one context. Doesn't generalize.
**You avoid this:** Decisions generalize beyond context.

### 20. MISSING INVARIANTS / UNCHECKED STATE
No verification state is valid. Assumes correct but doesn't verify.
**You avoid this:** Verify coherence explicitly. Don't assume.

# GATE_DIAGNOSIS_SIGNATURE_FRAMEWORK.md

## Core Principle: The Gate-Skipping Signature

Every human system has gates—thresholds of understanding that must be crossed to function coherently. When a gate is skipped (bypassed, delegated, or externally solved), the person develops a **signature mistake pattern** that:

1. **Appears domain-agnostic**: The exact same failure manifests in gardening, code, relationships, parenting, and professional work
2. **Repeats predictably**: The person encounters the same problem over and over, in different contexts
3. **Is diagnostic**: By observing the signature, you can identify the skipped gate with high precision
4. **Is testable**: Once identified, you can predict where the person will struggle in domains they haven't attempted yet

**Physics basis**: Skipping a gate doesn't make the gate disappear—it increases potential energy ($\Phi$) across all domains. The system naturally migrates toward failure until the gate is actually traversed.

## The 10 Gates & Their Signatures

### GATE 1: Cause-Effect Discovery
**Gate Principle**: Learning that actions reliably produce consequences; the world operates on discoverable cause-effect chains, not randomness.

**Signature Mistake**: "Outcomes appear random" / "Success is luck" / "Nothing I do matters"

**Why the Mistake Repeats**: If cause-effect isn't discovered, the person treats all domains as random systems. Each new attempt feels disconnected from planning. They experience each failure as surprising rather than predictable.

**The Logical Trap**: 
- Without cause-effect, planning feels pointless
- Without planning, outcomes truly become more chaotic
- Chaos confirms belief that cause-effect doesn't exist
- Deeper dependency on luck/external factors

#### Manifestation Across Domains

**Gardening**:
- Plants die unpredictably → "gardening is too hard"
- Doesn't track: watering schedule, sunlight, soil pH, drainage
- Next garden also fails → confirms randomness
- Diagnosis: Plants receive sporadic care; no observation of conditions before failure

**Programming**:
- Code "randomly" has bugs → "programming is luck"
- Doesn't debug systematically; tries random fixes
- Same bugs reappear in next project
- Diagnosis: No logging, no variable inspection, no test cases; "solution" found by accident, not theory

**Relationships**:
- Partners "randomly" leave → "I'm unlucky in love"
- Doesn't connect own behavior to partner's responses
- Repeats same patterns with each partner
- Diagnosis: No reflection on how their actions caused distance; sees each breakup as random event

**Parenting**:
- Child's behavior seems unpredictable → "kids are just difficult"
- Doesn't notice: child responded to a boundary, request, or consequence
- Next child exhibits "same problems" → confirms children are random
- Diagnosis: No tracking of what rule/consequence produced what behavior

**Professional Work**:
- Projects "randomly" fail → "management is luck"
- Doesn't connect project failure to earlier decisions
- Cannot explain why one approach worked and another didn't
- Diagnosis: No post-mortems, no causal analysis; "what happened" but not "why it happened"

**How to Diagnose Gate 1 Skipping**:
- Ask: "Why did that fail?"
- Listen for: "I don't know" / "just bad luck" / "random" / "happened to work"
- Observe: Do they explain via chain (A caused B caused C)? Or isolated events?
- Test: Ask them to predict the next outcome if they make the same choice
- If they can't, Gate 1 is skipped

### GATE 2: Responsibility Ownership
**Gate Principle**: Understanding that your choices are yours; accepting that outcomes follow from your decisions, not circumstances.

**Signature Mistake**: "It's always someone else's fault" / "External locus entirely" / "Circumstances control me"

**Why the Mistake Repeats**: Without ownership, the person never changes their own behavior—they only ask others to change. When others don't change, they're "defeated" again. Each failure confirms they're powerless.

**The Logical Trap**:
- "I'm not responsible" → don't change own behavior
- Own behavior stays the same
- Outcomes stay the same (because own behavior is unchanged)
- "See? I told you I can't control this"
- Deeper victim narrative

#### Manifestation Across Domains

**Gardening**:
- Garden fails → "the store sold me bad seeds" / "the weather was against me"
- Never returns to the same garden → can't improve it
- Next garden also fails → "I always get bad luck with plants"
- Diagnosis: Blames external factors; doesn't own: planting depth, watering routine, pest management

**Programming**:
- Code doesn't work → "the library is broken" / "the IDE is bad" / "JavaScript is terrible"
- Doesn't revise own code → writes same patterns next time
- Same errors recur → "this language is just impossible"
- Diagnosis: Blames tools/language/framework; never takes responsibility for debugging own logic

**Relationships**:
- Conflict happens → "they're impossible to deal with" / "they don't understand me"
- Never examines own contribution to conflict
- Next partner encounters same conflict → "I'm cursed with bad partners"
- Diagnosis: Can list partner's flaws in detail; cannot articulate own impact on dynamic

**Parenting**:
- Child misbehaves → "they're just a difficult child" / "bad genes" / "school is a bad influence"
- Doesn't examine own rules, consistency, or emotional response
- Repeats same parenting approach with same results
- Diagnosis: Detailed stories about child's defects; no acknowledgment of own decisions affecting behavior

**Professional Work**:
- Project fails → "my team was incompetent" / "management didn't support me" / "the client was unreasonable"
- Doesn't examine own planning, communication, or decision-making
- Repeats same project approach with same results
- Diagnosis: Explains failure entirely via others' actions; cannot name own choices that contributed

**How to Diagnose Gate 2 Skipping**:
- Ask: "What could you have done differently?"
- Listen for: Hesitation, or 0 answers, or "nothing, they were the problem"
- Observe: Does their explanation include their own choices? Their own options?
- Test: Ask them to describe the conflict from the other person's perspective (as an exercise)
- If they refuse or can't, Gate 2 is skipped

### GATE 3: Iteration & Mastery Through Repetition
**Gate Principle**: Understanding that mastery requires multiple attempts; each attempt refines skill; failures are data, not defeat.

**Signature Mistake**: "One attempt defines possibility" / "If it didn't work immediately, it can't work" / "Natural ability vs. learned skill conflation"

**Why the Mistake Repeats**: Without understanding iteration, the person quits after first failure. Quits confirm their belief that the task is "impossible for them." Next task, same pattern: one attempt, no improvement, quit.

**The Logical Trap**:
- "It didn't work immediately" → "I can't do this"
- Quit the task
- Never get the repetition needed for improvement
- "See? I was right, I can't do it"
- Deeper belief: ability is fixed, not developed

#### Manifestation Across Domains

**Gardening**:
- First plantings die → "I don't have a green thumb"
- Doesn't attempt same crop again to learn why
- Years pass, garden stays barren → confirms lack of ability
- Diagnosis: Gives up after one season; never observes what worked/didn't work in that season

**Programming**:
- First function doesn't work → "I'm not a programmer"
- Doesn't debug, doesn't refactor, moves to new language instead
- Next language also seems "impossible" → confirms fixed inability
- Diagnosis: Shallow attempt; declares technology "too hard"; moves to next language with same pattern

**Relationships**:
- First conflict with partner → "This isn't working"
- Doesn't practice conflict resolution, just leaves
- Next relationship has conflict (normal) → leaves immediately
- Diagnosis: Cannot stay present during difficulty; confuses normal struggle with fundamental incompatibility

**Parenting**:
- First attempt to establish boundary → child escalates
- Gives up on the boundary to stop escalation
- Never learns that consistency > initial escalation
- Diagnosis: Inconsistent rules that shift when child pushes back; child learns that escalation = boundary disappears

**Professional Work**:
- First project with new skill → mistakes happen
- Defensive about mistakes, doesn't continue learning skill
- Next project requires same skill → "I'm not good at X"
- Diagnosis: Blames role choice, company, or timing; never repeats attempt to master skill

**How to Diagnose Gate 3 Skipping**:
- Ask: "How many times have you tried that?"
- Listen for: "Once" / "A few times" (when mastery requires dozens)
- Observe: Do they improve from attempt 1 to attempt 5? Or quit?
- Test: Ask them what they learned from each attempt
- If they can't articulate learning progression, Gate 3 is skipped

### GATE 4: Pattern Recognition Across Domains
**Gate Principle**: Understanding that the same patterns repeat across different domains; recognizing structure, not just content.

**Signature Mistake**: "Everything is unique / context-dependent" / "No self-similarity" / "Can't apply learning from one domain to another"

**Why the Mistake Repeats**: Without pattern recognition, each domain feels completely new. The person relearns the same mistakes in each new context because they don't see the pattern connecting them.

**The Logical Trap**:
- "This is completely different from that"
- Don't apply lessons from one domain to another
- Make same structural mistakes in new domain
- "That domain's rules are just different"
- Never build cumulative understanding

#### Manifestation Across Domains

**Gardening & Programming**:
- Garden planning and code architecture are isomorphic (layered dependencies, timing, resource allocation)
- Person who sees pattern: "I'll assign my garden like I structure my codebase"
- Person who doesn't: treats them as completely separate skills, makes same layout mistakes in both

**Gardening & Relationships**:
- Both require: boundaries, regular maintenance, addressing small problems before they compound
- Person who sees pattern: "I need clear expectations here like I need clear spacing in plants"
- Person who doesn't: keeps boundaries in relationships fuzzy, keeps plant rows crowded, blames domain-specific factors

**Programming & Parenting**:
- Both require: clear specifications delivered through consistent interface
- Person who sees pattern: "I'll parent like I debug—understand the root cause, fix systematically"
- Person who doesn't: uses trial-and-error for both, doesn't look for root cause in either domain

**Professional & Relationships**:
- Both require: clear communication expectations, accountability, consequence for broken agreements
- Person who sees pattern: "I'll manage my team like I manage my partnership—clear, consistent"
- Person who doesn't: is professional in one context, avoids accountability in the other

**Manifestation**: 
- Diagnosis: Listen to how they describe domains. Do they use same vocabulary? Same conceptual framework? Or do they compartmentalize completely?

**How to Diagnose Gate 4 Skipping**:
- Ask: "What does this remind you of?"
- Listen for: "Nothing" / "This is just different" / "That doesn't apply here"
- Observe: Do they apply lessons from one context to another?
- Test: Teach them a principle in one domain, ask if it applies elsewhere
- If they say "maybe, but it's different here," Gate 4 is skipped

### GATE 5: Consequence Navigation (Living With Results)
**Gate Principle**: Understanding that choices have consequences that must be lived with; you don't get to undo, escape, or externally resolve your own choices' results.

**Signature Mistake**: "Escape/outsource/delegate when results are uncomfortable" / "Avoidance when facing own consequences" / "Dependency on others to resolve own choices' impacts"

**Why the Mistake Repeats**: Without consequence navigation, the person never experiences the full arc of their decisions. They escape before learning. Next decision, they also escape. No feedback loop.

**The Logical Trap**:
- Make choice, results appear uncomfortable
- Exit / delegate / have someone else handle it
- Avoid the learning that comes from living with choice's impact
- Next choice, same escape pattern
- Never develop judgment

#### Manifestation Across Domains

**Gardening**:
- Plant garden, realize it requires consistent work
- Abandons garden mid-season rather than commit to maintenance
- Next year, builds raised beds and leaves them → same cycle
- Diagnosis: Starts projects enthusiastically, quits when sustained effort required; never completes a full growth cycle

**Programming**:
- Writes code, realizes it has technical debt / maintainability issues
- Leaves project for new project instead of maintaining/refactoring
- Code accumulates across repos, all partially abandoned
- Diagnosis: Multiple half-finished projects; declares old code "legacy" immediately; avoids maintenance

**Relationships**:
- Relationship develops conflict or requires compromise
- Ends relationship (or cheats, or becomes emotionally unavailable) rather than navigate conflict
- Repeats pattern with next partner
- Diagnosis: Relationships always end when they "require too much work"; never stays through difficulty to resolution

**Parenting**:
- Child tests boundaries or requires correction
- Gives up on enforcement when child escalates/cries
- Repeats with next boundary: escalation makes them rescue instead of hold firm
- Diagnosis: Inconsistent parenting where child can escape consequences through emotional response

**Professional Work**:
- Takes role, realizes it's harder than expected
- Leaves role / delegates key responsibilities rather than improve
- Next role, same escape when difficulty arrives
- Diagnosis: Leaves jobs when they become challenging; doesn't stay to master role

**How to Diagnose Gate 5 Skipping**:
- Ask: "What happened when it got hard?"
- Listen for: "I left" / "Someone else handled it" / "It didn't work out"
- Observe: Do they stay present during uncomfortable phases?
- Test: Ask about their longest commitment and whether they ever stayed through difficulty
- If answers show exit pattern, Gate 5 is skipped

### GATE 6: Source Verification (Trinity: s ≠ ∅)
**Gate Principle**: Understanding that information has a source; you must know WHERE something comes from (origin, authority, evidence) before trusting it.

**Signature Mistake**: "Accepting information without source verification" / "Treating all claims as equal" / "No distinction between well-sourced and unsourced claims"

**Why the Mistake Repeats**: Without source verification, the person accepts claims from anyone. Gets bad information. Makes decisions on false beliefs. Doesn't connect the bad decision to the bad source.

**The Logical Trap**:
- Accept claim from any source
- Decision leads to bad outcome
- Don't trace back to evaluate source quality
- Make same source-verification mistake with next claim
- Increasingly vulnerable to manipulation

#### Manifestation Across Domains

**Gardening**:
- Takes plant care advice from anyone (internet stranger, acquaintance, random hobby blog)
- Plants die → doesn't evaluate source of advice
- Next plant, same: takes advice from someone with no expertise
- Diagnosis: Can't explain where advice came from or why they trust the source

**Programming**:
- Copies code from Stack Overflow without understanding it
- Code has security vulnerabilities / bugs
- Doesn't trace the problem to unverified source
- Next issue, copies more unverified code
- Diagnosis: Uses libraries/patterns without evaluating source credibility or testing

**Relationships**:
- Takes relationship advice from anyone (acquaintance, internet, people with failed relationships)
- Follows advice, damages relationship
- Doesn't question source quality
- Next relationship issue, same pattern
- Diagnosis: References vague "everyone says" or "I read" without evaluating source

**Parenting**:
- Takes parenting advice from anyone (random acquaintance, unsourced blog, people with no parenting experience)
- Advice damages parent-child relationship
- Doesn't evaluate source credibility
- Next parenting challenge, same pattern
- Diagnosis: Parents based on "what everyone does" rather than evidence-based or expert guidance

**Professional Work**:
- Takes business advice from non-experts (friends, unqualified colleagues, social media gurus)
- Advice leads to business damage
- Doesn't evaluate source authority
- Repeats with next decision
- Diagnosis: Can't articulate why they trust certain advisors; treats advice from successful people same as failures

**How to Diagnose Gate 6 Skipping**:
- Ask: "Where did you learn that?"
- Listen for: "I don't remember" / "Someone told me" / "I read it somewhere"
- Observe: Can they name the source? Evaluate its credibility?
- Test: Ask them why they trust that source over another
- If they can't justify source credibility, Gate 6 is skipped

### GATE 7: Time Coherence (Trinity: t ∈ T)
**Gate Principle**: Understanding that your timeline is continuous; every action exists in a causal sequence; you can't pretend today's choice is disconnected from yesterday's or tomorrow's.

**Signature Mistake**: "Timeline fragmentation" / "Acting as if history doesn't constrain present" / "No coherent life narrative"

**Why the Mistake Repeats**: Without time coherence, the person makes decisions without integrating past or future. Each decision feels isolated. They're surprised when past decisions constrain present options.

**The Logical Trap**:
- Make decision in isolation, ignoring past/future implications
- Face constraint from past or future
- Try to escape constraint instead of accept coherence
- Make next decision same way (ignoring timeline)
- Keep hitting timeline constraints

#### Manifestation Across Domains

**Gardening**:
- Plants succession without planning ahead → overcrowding
- Harvest schedule not coordinated → excess and shortage alternate
- Doesn't build on previous year's learning
- Diagnosis: No year-to-year consistency; each season treated separately; repeats mistakes from y1 in y2

**Programming**:
- Codes without considering how previous module interfaces with this one
- Creates incompatibilities, then fixes with hacks
- Architecture degrades over project duration
- Diagnosis: Early code fine, late code increasingly patched; no integrated architecture; doesn't plan API stability

**Relationships**:
- Makes commitment without honoring past commitment
- Creates conflict between obligations
- Doesn't integrate new partner into existing life structure
- Diagnosis: Neglects existing relationships when new one forms; creates schedule conflicts through poor planning

**Parenting**:
- Makes parenting decision that contradicts earlier boundary
- Child becomes confused about rules
- Repeats: inconsistent decisions across time
- Diagnosis: Rules that change based on mood, not principles; child can't predict parent; boundaries feel arbitrary or disappear

**Professional Work**:
- Makes hiring decision without considering team history
- Adds person who clashes with existing culture
- Repeats: doesn't learn from past hiring decisions
- Diagnosis: Doesn't consult past performance data when making decisions; repeats same mistakes in hiring/firing

**How to Diagnose Gate 7 Skipping**:
- Ask: "How does this connect to what you did last year?"
- Listen for: "I don't think about that" / "That's separate" / "Not relevant now"
- Observe: Do they track their own history? Build on it?
- Test: Ask them to show how a current decision integrates with past commitments
- If they can't or won't, Gate 7 is skipped

### GATE 8: Causality Verification (Trinity: v⃗ = true)
**Gate Principle**: Understanding WHY something must be done (not just WHAT or HOW); connecting action to value, consequence, or principle; walking the causal chain from effect back to reason.

**Signature Mistake**: "Following rules without understanding why" / "Dogmatic adherence to patterns" / "Cannot explain the reason for doing something"

**Why the Mistake Repeats**: Without causality verification, the person follows patterns without understanding them. When context changes, the pattern fails. They don't understand why, so they try the same pattern anyway.

**The Logical Trap**:
- Learn rule/pattern without understanding reason
- Apply rule in wrong context (because you don't understand reason)
- Pattern fails
- Don't understand why it failed → don't learn
- Try same rule in next context
- Fails again

#### Manifestation Across Domains

**Gardening**:
- Learns: "plant in spring"
- Doesn't understand why (growth season, soil thaw, day length)
- Plants spring crop in area with short spring → fails
- Doesn't understand connection between reason and rule
- Next year, tries "spring planting" in area with different climate → fails again
- Diagnosis: Follows rules, but can't explain why; can't adapt rule to new context

**Programming**:
- Learns design pattern (MVC, DRY, SOLID)
- Doesn't understand why (separation of concerns, maintainability, scalability)
- Applies pattern inappropriately (e.g., DRY to a one-time utility)
- Pattern creates problems; doesn't understand why
- Still applies same pattern in next project regardless
- Diagnosis: Uses terms like "best practice" but can't explain the reasoning; can't decide when pattern doesn't apply

**Relationships**:
- Learns: "never go to bed angry"
- Doesn't understand why (unresolved conflict festers, disconnection worsens)
- Uses rule dogmatically: keeps partner awake at 3 AM to resolve trivial conflict
- Rule now creates problems; doesn't understand why
- Keeps rule rigidly despite harm
- Diagnosis: Follows relationship advice without understanding principle; can't adapt guidance to situation

**Parenting**:
- Learns: "positive reinforcement works"
- Doesn't understand why (behavior reinforced is behavior repeated, so reinforce desirable behavior)
- Reinforces undesirable behavior by celebrating it enthusiastically
- Repeats behavior intensifies; doesn't understand why rule failed
- Keeps applying rule anyway
- Diagnosis: Uses techniques without understanding mechanism; can't diagnose when technique backfires

**Professional Work**:
- Learns: "delegate to empower"
- Doesn't understand why (empowerment requires growth, feedback, accountability, safety)
- Delegates without support structure → person fails, feels unsupported
- Delegation fails; doesn't understand why principle didn't work
- Next delegation, same approach, same failure
- Diagnosis: Follows management advice without understanding principle; can't adapt to person's needs

**How to Diagnose Gate 8 Skipping**:
- Ask: "Why does that work?"
- Listen for: "That's just the rule" / "Everyone does it" / "I was taught that"
- Observe: Can they explain reasoning? Can they adapt when context changes?
- Test: Change context, ask if rule still applies (watch if they understand why or just follow pattern)
- If they can't explain principle, Gate 8 is skipped

### GATE 9: Self-Correction & Evidence Integration
**Gate Principle**: Understanding that evidence can contradict your beliefs; you can change direction when evidence shows failure; correction is strength, not weakness.

**Signature Mistake**: "Defending failing approach despite evidence" / "Stubbornness as virtue" / "Cannot admit when wrong; doubles down instead"

**Why the Mistake Repeats**: Without self-correction, the person ignores evidence. Same approach fails repeatedly. They keep trying same thing because admitting failure feels like identity threat.

**The Logical Trap**:
- Approach fails
- Evidence (data, outcome, feedback) shows failure
- Doesn't want to admit wrong → defend approach
- Keep defending → keep trying same approach
- Same failure repeats
- "See? I was right to keep trying" (confusing tenacity with wisdom)

#### Manifestation Across Domains

**Gardening**:
- Intercropping method fails (incompatible plants)
- Harvest shows failure clearly
- Insists method is right, problem is external (weather, soil, strain)
- Tries same method next year → same failure
- Never tests alternative → never improves
- Diagnosis: Can't acknowledge when approach isn't working; blames external factors instead of adjusting method

**Programming**:
- Algorithm is inefficient (performance test proves it)
- Defends algorithm instead of optimizing
- Refuses to profile code, refuses to benchmark alternatives
- Next deployment, same performance problems
- Never fixes underlying approach
- Diagnosis: When feedback shows issue, becomes defensive; insists on keeping approach that's proven inefficient

**Relationships**:
- Communication style repeatedly causes conflict
- Partner gives feedback: "how you talk to me damages us"
- Defends communication style instead of changing it
- Next conflict, same communication pattern, same damage
- Refuses couples counseling that would show pattern clearly
- Diagnosis: Receives feedback about behavior, rejects it rather than integrate it; blames partner for "not understanding"

**Parenting**:
- Parenting approach repeatedly fails (child escalates, relationship damaged)
- Child's behavior shows approach isn't working
- Defends approach instead of analyzing
- Tries "harder" with same approach → same failure
- Never seeks parenting education or changes strategy
- Diagnosis: Recognizes child's behavior is problematic, doesn't examine own approach; doubles down on what's failing

**Professional Work**:
- Project is failing (timeline, budget, quality)
- Project metrics prove failure
- Defends project decisions instead of recognizing failure
- Keeps sinking resources instead of pivoting
- Never establishes Go/No-Go criteria
- Diagnosis: Clear metrics show failure, keeps defending approach; treats acknowledging failure as personal attack

**How to Diagnose Gate 9 Skipping**:
- Ask: "What evidence would show you this approach isn't working?"
- Listen for: "Nothing" / "It will work eventually" / defensive response
- Observe: When they receive negative feedback, do they integrate or defend?
- Test: Point out specific evidence against their approach, watch how they respond
- If they defend rather than consider, Gate 9 is skipped

### GATE 10: Integration & Holding Paradox
**Gate Principle**: Understanding that multiple perspectives can be true simultaneously; you can hold complexity without collapsing to simplicity; contradictions can coexist without invalidating either.

**Signature Mistake**: "Black-and-white thinking" / "False dichotomy" / "Collapse to simplest narrative instead of holding complexity"

**Why the Mistake Repeats**: Without integration, the person simplifies complex situations into good/bad, right/wrong. When complexity reasserts itself, they're confused. They re-simplify instead of holding multiple truths.

**The Logical Trap**:
- Encounter complexity (person is both kind AND wrong, situation is both success AND contains failure)
- Discomfort of holding contradiction
- Collapse to simpler narrative
- Real complexity returns
- Re-collapse to new simple narrative
- Swing between extremes, never integrate

#### Manifestation Across Domains

**Gardening**:
- Plant is both "thriving" (new growth) AND "sick" (leaf spotting)
- Collapses to: "plant is ruined, remove it" OR "plant is fine, ignore spotting"
- Never holds: "plant is growing but needs intervention for disease"
- Collapses to extremes instead of managing complexity
- Diagnosis: Gardens show black-and-white management (all thriving or all dying); can't maintain partial health states

**Programming**:
- Code is both "working" (core function runs) AND "broken" (memory leak, security vulnerability)
- Collapses to: "code is production-ready" OR "code is garbage, rewrite"
- Never holds: "code works AND needs refactoring AND needs hardening"
- Treats code as all-good or all-bad
- Diagnosis: Code reviews show: all praise or all criticism; can't acknowledge simultaneous good design AND technical debt

**Relationships**:
- Partner is both "loving" AND "hurtful"
- Collapses to: "partner is wonderful, overlook hurt" OR "partner is toxic, must leave"
- Never holds: "partner is fundamentally good AND this behavior is unacceptable"
- Swings between extremes
- Diagnosis: Describes partners as all-good ("they saved me") or all-bad ("they destroyed me"); can't maintain both truths at once

**Parenting**:
- Child is both "good kid" AND "currently misbehaving"
- Collapses to: "child is good, excuse behavior" OR "child is bad, harsh punishment"
- Never holds: "child is good AND this behavior is unacceptable AND I'll address it"
- See misbehavior as character rather than action
- Diagnosis: Praises child indiscriminately OR criticizes constantly; can't separate behavior from identity

**Professional Work**:
- Team member is both "competent at task A" AND "weak at task B"
- Collapses to: "hire/promote" (ignore B) OR "reject" (focus only on B)
- Never holds: "promote selective to A, develop B, or train differently"
- Treats people as all-capable or all-incapable
- Diagnosis: Hires for perfect fit (impossible) or rejects for any weakness; can't develop people in complexity

**How to Diagnose Gate 10 Skipping**:
- Ask: "Can both of these be true at the same time?"
- Listen for: "No, one of them has to be wrong" / collapse to binary
- Observe: Do they acknowledge nuance, or simplify to extremes?
- Test: Describe someone/situation with two opposing qualities, watch if they can hold both
- If they force resolution to one pole, Gate 10 is skipped

## THE DIAGNOSTIC METHOD: How to Identify Skipped Gates

### The Observation Process

You identify a skipped gate by **observing failure patterns domain-agnostic**:

1. **Watch a person operate across domains** (work, relationships, gardening, learning, projects)
2. **Identify the failure pattern** (what keeps going wrong, despite context changing?)
3. **Check if pattern repeats identically across domains**
4. **That pattern IS the signature** of a skipped gate
5. **Match signature to gate** using the framework above
6. **Prediction becomes possible** — you now know where they'll struggle next

### Testability & Predictability: What Makes This Framework Scientific

**The hypothesis**: "Person X has skipped Gate Y"

**The test**:
1. Observe person X across multiple domains
2. Identify the failure signature
3. Match to gate framework
4. **Predict** where they'll struggle in domains they haven't attempted
5. When they attempt new domain, observe if prediction comes true

**Result**: Framework is **falsifiable and testable**
- If person skipped Gate 5, they will exit when things get hard (testable)
- If person skipped Gate 3, they will quit after few attempts (testable)
- If prediction doesn't come true, hypothesis is wrong, framework needs refinement

### Why This Matters

A framework that is merely descriptive ("here are 10 gates") is limited.

A framework that is **diagnostic** ("identify person's skipped gate by observing signature") is more useful.

A framework that is **predictive** ("given their signature, I can predict their struggles in new domains") is scientific.

**This framework is the third type**: You can identify the gate, see the signature, and predict future failures with high precision.

## Conclusion

This framework is testable, predictive, and domain-agnostic. It reveals that **each person's struggles are not random—they are signatures of specific skipped gates**. 

By observing a person across domains and identifying their signature mistake pattern, you can:
- **Diagnose** which gate they skipped
- **Predict** exactly where they'll struggle next
- **Understand** why the same problem repeats across all their domains
- **Know** what authentic passage would look like (and that no scaffolding can replace it)

The framework proves itself through consistency: the same gate-skip produces the same damage pattern everywhere it's attempted.

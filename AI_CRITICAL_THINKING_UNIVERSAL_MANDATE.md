## THE CORE REQUIREMENT

**Before any AI produces output, it MUST apply critical thinking frameworks.**

This is not optional. Not negotiable. Not "when we remember."

Every major project, code generation, analysis, or planning task must follow this sequence:

```
1. THINK through binary logic completely (THINKING_FIRST)
2. Plan through coherence tiers (SIX_TIERS)
3. Verify using TCHT framework (TIERS -1 through 3+)
4. LOG all decisions and reasoning (DECISION_TRANSPARENCY)
5. Then produce output
6. VERIFY output matches thinking
```

## THREE MANDATORY FRAMEWORKS

### FRAMEWORK 1: THINKING_FIRST_FRAMEWORK
**File**: `/memories/THINKING_FIRST_FRAMEWORK_CORE.md`

**Purpose**: Never code until thinking is complete

**The Inversion**:
- ❌ Code first → Run → Debug → Hope it works
- ✅ Think completely → Code → Verify → Works first try

**How It Works**:
1. Trace all 0,1 branches (all possible states)
2. Map all causal chains (how each input affects output)
3. Verify no gaps remain (full coverage analysis)
4. Only THEN write code as verification
5. If code fails → something in thinking was incomplete

**When Code Fails**: This is not a "bug." It's data that your thinking had gaps.

---

### FRAMEWORK 2: TCHT SELF-APPLICATION
**File**: `/memories/TCHT_SELF_APPLICATION.md`

**Purpose**: Verify work through 5 tiers before delivery

**The 5 Tiers** (Applied to YOUR own work):

**Tier -1 (Honesty/Self-Awareness)**
- What did I actually verify? (not what I hope is true)
- What am I assuming without checking?
- Red flags: "It compiled so it works" or "I read 10 lines and assumed the rest"
- ✓ Resolution: Be explicit about what you know vs. assume

**Tier 0 (Surface vs. Real)**
- What problem am I actually solving?
- Is it the same problem the user asked for?
- Red flags: Confusing "looks right" with "works right"
- ✓ Resolution: Distinguish appearance from substance

**Tier 1 (Root Cause)**
- List 3-5 ways this could fail
- Trace the causality chain for each failure
- Fix root causes, not symptoms
- Red flags: "This fixes the obvious part, should cover it"
- ✓ Resolution: Go to the source, not the symptom

**Tier 2 (Consistency)**
- Did I apply this standard everywhere, or only partially?
- Would yesterday's work have the same issues?
- Red flags: "I fixed tier_3 but not tier_1" or "some files but not all"
- ✓ Resolution: Same standard everywhere

**Tier 3+ (Integration)**
- Is this automatic, or manual?
- Do I apply this BEFORE producing output, not after user questions it?
- Red flags: Applying framework after getting questioned
- ✓ Resolution: Make it your default thinking process

**Before Delivering**: Work through all 5 tiers. If any reveals an issue, FIX IT NOW.

---

### FRAMEWORK 3: SIX TIERS OF COHERENCE
**File**: `/memories/the-six-tiers-of-coherence-gain.md`

**Purpose**: Progress from understanding to action to validation

**The Progression**:

| Tier | Action | Coherence | Proof |
|------|--------|-----------|-------|
| 1 | IDENTIFY | 99.7% | Problem acknowledged |
| 2 | ENGAGE | 99.75% | Others witness it |
| 3 | UNDERSTAND | 99.9% | Shared meaning built |
| 4 | ACT | 100% | Solution implemented |
| 5 | COORDINATE | 100% | Multiple instances aligned |
| 6 | VALIDATE | 100% | Works at production scale |

**Key insight**: Can't skip tiers. Can't jump from IDENTIFY directly to ACT without building understanding first.

**For any task**:
1. Have I identified the real problem? (Not surface, real)
2. Have others engaged? (Is thinking witnessed?)
3. Is there shared understanding? (Can we explain what we're doing?)
4. Is concrete action happening? (Not just talk, actual change)
5. Is this coordinated with other instances? (Or isolated thinking?)
6. Does it validate in reality? (Not theory—proven outcomes)

## DECISION LOGGING REQUIREMENT

Every decision must be logged with:

```
DECISION: [What choice is being made?]
REASONING: [Why this choice? What framework supports it?]
ALTERNATIVE: [What else could be done? Why not?]
VERIFICATION: [How will we check this works?]
LOGGED: [Who, what, when, why this matters]
```

Example:
```
DECISION: Use TCHT Tier 1 verification before deploying SVG generators
REASONING: Previous failure (Unicode corruption) teaches we skip root causes
ALTERNATIVE: Visual inspection only; Risk: Same error repeats
VERIFICATION: All generators tested with special characters; encoding logged
LOGGED: April 19 - Prevents repeated failure patterns
```

## INTEGRATION INTO WORKFLOW

### For Each Task:

**STEP 1: THINK (using THINKING_FIRST)**
- Map complete binary logic
- Trace all branches
- Verify no gaps

**STEP 2: PLAN (using SIX_TIERS)**
- Identify problem (what are we really solving?)
- Engage with user (is approach understood?)
- Build understanding (can we explain it?)

**STEP 3: VERIFY (using TCHT)**
- Tier -1: What did I actually think through?
- Tier 0: Surface vs. real problem?
- Tier 1: What could break? Trace each cause
- Tier 2: Is this consistent everywhere?
- Tier 3: Is this automatic thinking now?

**STEP 4: LOG (using DECISION format)**
- Log major decisions and why
- Document verification performed
- Record assumptions explicitly

**STEP 5: PRODUCE**
- Code, plans, solutions, analysis
- MUST pass all 4 previous steps

**STEP 6: VALIDATE**
- Does output match thinking?
- If no → something in thinking was incomplete
